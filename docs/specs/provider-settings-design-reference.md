# LLM Providers · 高保真原型与接入规范

> **原型，不是生产实现。** 分支 `prototype/provider-settings-system-v2`，基于线上 UI v0.1.12。
> 只操作浏览器内存；不调用真实授权、额度或保存接口，不影响 3080。
> 用户尚未选定方案，不声称某一个方案已被验证优于其他方案。

## 打开原型

~~~sh
cd /home/noirbright/Workstation/.worktrees/dsh-provider-settings-system-v2
pnpm run prototype:providers
~~~

打开 **http://127.0.0.1:4186/provider-settings-system.html?variant=A&frame=800**。
底部工具条支持 A/B/C 切换、800/1040/390 宽度、深浅主题、状态预览、完整内存状态和重置。左右方向键也能切换方案；输入框、下拉框、对话框不会误触。

原型参照真实 Settings 导航、品牌 SVG、灰阶语言与圆角层级，不是脱离应用的概念海报。800 是原设置窗口尺寸，1040 是待评审的宽屏选项；390 可在桌面模拟窄屏，真实窄屏也自适应。没有给主应用增加路由，采用已有 `prototypes/` 静态预览约定，遵守“不改生产代码”的要求。

| 方案 | 核心结构 | 要回答的问题 |
|---|---|---|
| A · 统一列表 | 身份/状态在左，等宽额度摘要在右，配置就地展开 | 能否保留熟悉的浏览路径，同时消除各 Provider 自行排版？ |
| B · 主从面板 | Provider 导航＋完整配置面板，窄屏导航变横向条 | 经常切换 Provider 时，是否比不断展开长列表更清晰？ |
| C · 额度总览 | LLM/Agent 筛选的额度台账＋独立配置页 | 是否应该明确分开“看额度”和“改配置”？ |

三者共用**同一份完整控件与状态**，不是三个能力不对等的效果图。切换方案保留账号状态、模型编辑和排序草稿。

## 统一信息结构

1. **身份**：品牌、名称、LLM/Agent 角色、模型数、连接状态、未保存标记。插件开发状态与账户状态分开。
2. **账号与连接**：OAuth、设备码、粘贴授权码、API Key、原生 CLI 保留各自真正支持的交互，但位置与状态语言一致。
3. **剩余额度**：窗口、剩余百分比、重置时间、刷新、更新时间。金额、积分、Token 等非百分比信息放入独立事实区，不假装成进度条。
4. **模型**：参照 DSH 模型设置的双态行。ID、名称、展开箭头、删除按钮常显；容量、视觉、推理与思考等级可独立展开/收起，也可一键全部展开/收起。沿用先前默认展开的偏好；视图状态不算配置更改。目录搜索、多选、排序、添加、删除、撤销均保留。
5. **高级设置**：确实存在额外能力或连接参数时才出现，默认关闭，展开后保留全部依赖选项。没有额外设置的 Provider 不渲染空折叠框。
6. **提交**：有草稿时显示明确作用于当前 Provider 的保存/放弃栏。切换 Provider 不偷偷保存、不丢弃其他草稿。失败与冲突保留编辑内容。

## 额度展示契约

共享呈现 module 只接收已解码的**剩余量**；Provider adapter 负责转换 used%、remaining%、0–1 fraction，不能把“已用”当成“剩余”。

- 恢复现有 ProviderQuotaMeter 的 **10 格**设计：6px 高、2px 圆角、1px 分格间隙、填充末端 2px 标记；低于 20% 才用琥珀色，不新增红色分档。同层级轨道等宽；详情单列窗口。源码依据：`src/client/provider-ui.tsx:66–118`。
- 文本取整数；填充和状态判断保留原值。49.9 显示 50%，不修改输入，也不能用取整后的值判断是否真正为零。
- 拒绝 NaN、无穷和 0–100 之外的数据，不静默 clamp 成满额或空额。缺失不是 0。
- `resetsAt` / `resetTime` 保留原始绝对时间，统一由呈现 module 格式化。原型固定 UTC+8 并显示时区；实施时跟随用户设置，摘要与详情使用同一个格式化函数。
- 精确时间：**重置于 09/15 00:00 · 5天后**；到期但未更新：**已到期，等待更新**。
- 只有周期：**每周 · 重置时间未提供**，不能从“每 7 天”推算一个假精确日期。
- 加载中显示加载状态；失败有缓存保留旧值并标注缓存；失败无缓存不画条；不支持接口明确说明。登录不支持额度的 Provider 后也不能突然出现条形。
- 窗口名称、分组、余额与活动统计来自 Provider。共享 module 不硬编码 Gemini/Claude 是唯一 Agent 分组。

**演示数据说明：**主要比例参考用户截图，补充窗口是明确标注的示例，绝非实时读取。时间基准固定为 2026-09-10 09:34（UTC+8），便于截图对比。原型的相对时间不会随机器当前时间漂移。

## 排序：一个入口、一种可见移动方式

Provider 与模型排序都**留在原设置页面，不开 overlay / dialog**。进入排序状态后，当前列表临时精简为手柄、品牌/名称、Model ID（模型行）、角色和位置；底部原有操作区显示取消/完成。排序期间暂停其他编辑，避免配置和顺序混合提交。**不拖动完整表单，不同时增加上下箭头按钮。**

- 鼠标/触摸拖同一个手柄；键盘聚焦手柄后用 ↑/↓。
- 屏幕阅读器宣布新位置；手柄触摸不与页面滚动竞争，列表边缘可滚动。
- 取消保留原顺序，完成才应用；Esc 始终等同取消整个排序，包括拖动中，避免触摸 pointercancel 与按键顺序的歧义。模型排序之后仍需保存模型草稿。
- 排序不改变连接状态、模型内容或其他 Provider 草稿。退出后恢复各行展开/收起状态；切换 A/B/C 也不丢失待确认顺序。
- 模型排序只精简模型区域；Provider 排序在当前内容区精简全局列表。拖动浮影仅用于指针反馈，不是排序 overlay。

## 手机 APP 布局

- 主导航在窄屏改为横向滚动；模型 ID 与名称换行排列，不把两个输入和两个按钮硬塞进一行。工具栏随宽度换行。
- 主要触控目标至少 44×44px；手机输入字号 16px，避免 iOS 聚焦时自动放大。所有参数仍可编辑，不另做功能缩水版。
- 使用 `viewport-fit=cover`、安全区 inset、动态可视高度。原生 SettingsRoot 尚无这些处理，此处是新增的手机适配，而非声称已经部署。
- 短视口/软键盘场景精简导航和原型工具条；排序中暂藏主导航/顶部栏并直接定位列表行，保证可见手柄，而不只是容器存在。保留滚动内容与底部提交区，提示消息避开提交区和原型工具条。通过 VisualViewport 跟随可视空间；不禁用用户缩放。
- 排序采用单一触摸手柄，支持边缘连续滚动；取消/完成在原页面底部，不占用新的弹窗空间。
- 使用 Chromium 手机尺寸和触摸模拟验证；不冒充 iOS/Android 真机 APP 验收。

## 新 Provider 接入规范

生产已有 seam：`ProviderDirectory.register` + `settings.provider.item`。已有共享出口：`dsh-llm-providers-ui/provider-ui`、`./model-catalog`、`./usage-readers`。后续实施先复用，不再建立另一份按插件名称分支的展示表。

**插件提供数据与行为 adapter，共享 module 拥有视觉和交互：**

1. 注册稳定键与角色。Cursor LLM 与 Cursor ACP 不能共用身份。原型短 ID 仅用于演示；Cursor ACP 实际 native provider key 为 `cursor-agent`。
2. 提供连接状态和真实可用的认证操作。OAuth/设备码/CLI 属于 adapter；不能从相似卡片复制不存在的 action。
3. 提供可选额度 reader：原始窗口 ID/名称、剩余量、精确重置时间、读取状态与时间。没有接口则声明 unsupported。
4. 提供目录与逐模型能力，包括可用思考等级。不能把 Provider 全集套到每个模型；手动模型才使用 Provider 级兜底。
5. 可选能力只声明真正可用的字段与依赖关系，由共享高级区域呈现。不另外定义标题、条形宽度、日期文案或模型折叠方式。
6. 凭据留在 Host 凭据存储，UI 只接收安全状态。密码草稿只在当前页专用内存中暂存，重绘保持输入；保存/放弃/重置后清除，不进入日志、状态预览、DOM value 属性或持久化。更换密钥后清除旧账号额度，等待重新读取。
7. 实施仍需处理 revision 冲突、认证/网络失败、凭据与配置部分成功，不能把原型定时器简单替换成无条件成功的 RPC。

**Cursor ACP 核验样例：**已实现的 CLI 登录、目录分组映射进框架；quota host 不支持，则不画条。复制来的 Google localhost 回调和 cancel-login 没有 Host handler，不在界面上承诺。运行时路径、权限模式、重试策略不是当前设置卡的现成功能，不为“填满高级设置”而增加。
