# Provider settings · 高保真原型任务

状态：三套高保真交互原型已完成并通过浏览器检查；等待用户选择方案。未改动生产代码或部署到 3080。

入口与接入规范见 `provider-settings-design-reference.md`。原型：`http://127.0.0.1:4186/provider-settings-system.html?variant=A&frame=800`。

## 原型要回答的问题

在现有 DSH Settings 外壳中，哪一种信息结构能同时支持多 Provider 额度浏览与完整配置，又不让排序、模型和高级能力相互挤压？

三种结构，单个原型页面通过 `?variant=A|B|C` 切换：

- A：统一列表，Provider 详情就地展开。
- B：Provider 导航＋专注详情，切换 Provider 不丢弃各自草稿。
- C：额度总览＋独立详情，浏览与配置分开。

三个方案不是换色；布局、信息层级、导航方式不同，功能覆盖保持相同。尚未验证哪个方案胜出。

## 已确定的设计约束（来自用户要求）

1. 全部百分比表示各自账户的**剩余额度**，文本取整数；不把不同 Provider 的额度相加。恢复现有 10 格额度条，统一轨道高度与同层级宽度。
2. `resetsAt` 保留原始时间戳，由共享展示统一生成“重置于 日期 时间 · 剩余时长”，时区可见；未知精确时间显示“重置时间未提供”，只有周期不能伪装成倒计时。
3. 根据最新反馈，模型行需有展开/收起两态，参照 DSH 模型设置；ID/名称常显，容量与能力参数可收起。保留此前默认展开偏好，提供逐行及全部展开/收起。
4. 高级设置默认折叠；展开后保留每个已实现能力的完整子选项。不会把未渲染的 locale 文案当成现有功能。
5. 根据最新反馈，排序直接在现有页面进入精简状态，不开 overlay；保留名称、ID、角色和单一手柄，不拖完整表单、不重复增加上下箭头按钮。底部取消/完成；退出恢复展开状态与草稿。
6. 没有额度接口、加载中、读取失败、旧数据、未登录、真正 0% 分开呈现，不能全部画成空条。
7. API key / OAuth / Native Agent 登录方式不强行变成相同表单；统一的是分区、状态语言与操作位置。
8. 模型目录的 ID、名称、上下文、视觉、推理与默认思考等级全部可编辑；按真实 Provider 支持显示选项，保留获取目录、搜索选择、手动添加、删除、排序、保存和放弃草稿。
9. Cursor ACP 清楚标记为开发中接入示例，不能把尚未安装或尚未实现的能力标为线上可用。

10. 手机 APP 是明确设计目标：窄屏字段与操作区重新排布，44px 触控目标，安全区和短视口适配，验证触摸排序与边缘滚动。

## 高保真要求

复用真实品牌 SVG，参照现有 SettingsRoot 的 800px 外壳、188px 主导航、32px 圆角与原生设计 token。测试原尺寸、宽屏、窄屏及深浅主题。原型中的按钮必须有对应的可观察交互，不是仅能看的截图。

数据全部为明确标注的演示数据。所有变更仅在内存中；不调用真实登录、保存配置或消费额度的接口，不填写真实凭据。切换方案与关键操作后展示可审阅状态。
