# Provider Settings — selected A prototype

User decision: A (inline accordion), not B or C. Remove decorative role stripes, tinted badges, rounded card stacks, marketing-style headings and ornamental progress bars. Current visual revision is pending user confirmation. Earlier alternatives remain in this throwaway branch history: `prototype/provider-settings-three`; do not merge prototype code into production.

Run: `python3 -m http.server 3083 --bind 127.0.0.1 --directory src/client/prototype`. Open <http://127.0.0.1:3083/providers.html?variant=A&theme=light> or use `theme=dark`. The preview control switches themes; the initial system preference applies when no theme is specified.

The page is a plain divided settings list. LLM uses an outlined monochrome message badge; Agent uses a filled monochrome terminal badge, without a provider side accent. Quota summaries and details show thin segmented meters with exact remaining percentages; low quota is amber, otherwise neutral. All provider icons reuse local assets: five shared providers-ui BrandMarks, Grok redrawn from the user reference (grok.svg), the supplied Antigravity SVG and the bundled DSH DeepSeek favicon, all adapted to currentColor in icons.js. On phones the summary occupies a second row and expanded windows use a single column.

All accounts, capabilities, model names and quota values are illustrative. Settings navigation is a labeled replica, not the live DSH shell. No real authentication, API requests, storage or profile mutations occur. Model enablement, thinking/vision toggles, default effort, context window and model order are editable in memory and participate in save/cancel. Disabling thinking resets default effort, matching the existing Codex menu behavior. Effort choices are prototype fixtures; production must use each provider/model metadata, not assume identical support. Provider order changes in memory using a dedicated sorting mode. Both sorting modes support pointer/touch handles and up/down controls; grip arrow keys also work. Drop-only dragging is a deliberate prototype simplification; production reuses SortableList live preview and auto-scroll. Runtime advanced fields and routing/catalog buttons remain stubs. Adding providers and lifecycle behavior are outside this visual prototype. No 3080/3082 artifacts are changed.

Run `node src/client/prototype/check.mjs` with Chrome CDP on `127.0.0.1:9228`. It checks light/dark at 1280/390/320px, zero Agent side border, collapsed/expanded/menu/sort overflow, all eight SVG icons, model changes and save, thinking/effort interaction, model order and actual mouse/touch provider dragging. Screenshots: `/tmp/provider-clean-{1280,390,320}-{light,dark}.png`.
